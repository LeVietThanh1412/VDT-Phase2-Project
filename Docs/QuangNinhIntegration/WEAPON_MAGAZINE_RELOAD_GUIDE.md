# Shared magazine and reload

Single authority: UShipWeaponComponent, shared by player FirePlayer and AI TryFireWeapon. Defaults are MagazineCapacity=10 and ReloadDurationSeconds=30; both are editable Blueprint class defaults. RoundsRemaining, Reloading, ReloadsStarted/Completed are read-only runtime diagnostics.

Only a valid projectile accepted inside the original synchronous ExecuteWeaponShot dispatch consumes a round in FinishShot. A duplicate callback for the same round does nothing. One dispatch accepts at most one round. Missing/invalid spawn, rejected input, recoil/cooldown, invalid aim/target, inactive turn and destroyed ship consume zero rounds. Profile application and target/aim changes do not initialize the magazine again.

After the tenth accepted round, BeginReload starts one world timer and records an absolute game-world deadline. Further inputs cannot start another reload or fire. CompleteReload restores capacity once after the deadline. It runs while another ship owns a turn: action windows do not pause the timer. World pause pauses game time. Death cancels the timer and blocks firing; EndPlay cancels it. A new level/match instance initializes a fresh magazine.

The native UShipHUDWidget adds AmmoText and its visible text block. It reads the player's weapon each refresh: AMMO: 7/10 or AMMO: 0/10 | RELOADING: 00:29. Countdown uses ceiling of authoritative remaining world time; the HUD cannot refill or unlock firing. A destroyed player's HUD reads WEAPON OFFLINE.

Blueprint setup: retain the existing ExecuteWeaponShot and its FinishShot call before original FX/recoil. Do not call FinishShot directly to create extra rounds; it rejects calls outside dispatch. Keep original projectile damage and projectile movement components. Do not add competing counters in controllers, projectiles or widgets.
