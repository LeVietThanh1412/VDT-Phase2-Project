# Known limitations

- Project is a technical demonstration, not a certified maritime training/fire-control system. Gameplay-scaled mass/speed/damage, simplified pontoons and wreck animation are not vessel-identification data.
- Terrain is dataset/LOD-specific. Collision handling separates raw coast from navigation exclusion, but no bathymetric survey or all-LOD correctness certificate exists.
- New source/reflection inspection does not rerun historical long matches. All runtime claims retain scenario and DLL/source boundary.
- Seed repeatability is layout/configuration dependent, not bitwise reproducible physics or guaranteed winner. Alternative fleet/path reverse-flow stress cases failed in retained evidence.
- Small has no skeleton of its own. Its gun integration reuses the original skeletal driver. Three profiles do not imply three independent artistic hulls.
- Difficulty parameters are implemented and selectable; comparative hit-rate efficacy is not measured.
- Map mouse smoke through desktop injection was inconclusive. Native hit-test/Enhanced Input/modal/follow checks passed. Real held-Alt dragging/focus loss and physical RMB+LMB remain manual smoke checks.
- Portable terrain staging/resolver is on package, not main. Do not use historical packaged artifacts as a current-main delivery certificate.
- Multiplayer/replication, every platform, memory leak freedom and packaged GPU performance are not established.
- Current-main native source uses Actor Tags for descriptive identity with numeric team authority; do not advertise a Gameplay Tags framework integration merely from terminology.
- Full Blueprint source coverage is limited to accessible graph exports, reflected settings, component/asset inspection and saved tests. Not every material/animation node was reverse-engineered.
- Individual authorship is not assigned without task records. Brand/logo supplied by user; external asset license confirmation is documented as such.
